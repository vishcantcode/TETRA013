## SECTION 3 — DOMAIN MODEL

The CSE domain is entirely immutable. Once a scenario or projection is generated, it cannot be modified, only superseded by a new simulation request.

### Core Entities

#### `SimulationRequest`
- **Purpose:** Encapsulates the inputs required to begin a simulation.
- **Lifecycle:** Created by an external consumer (e.g., Care Planning module). Ephemeral.
- **Relationships:** Contains `DigitalTwinSnapshot`, `CKFVersionId`, and an array of proposed `ClinicalIntervention`s.
- **Invariants:** Must have exactly one deterministic `CKFVersionId` and one immutable `DigitalTwinSnapshot`.

#### `SimulationScenario`
- **Purpose:** Represents a single bounded projection pathway.
- **Lifecycle:** Generated by the CSE Pipeline. Persisted for audit/replay.
- **Relationships:** Belongs to a `SimulationRequest`. Contains one `ScenarioTimeline`.
- **Invariants:** The projected state must never mutate the original `DigitalTwinSnapshot`.

#### `ClinicalIntervention`
- **Purpose:** Represents the action being simulated (e.g., "Start Lisinopril 10mg daily").
- **Relationships:** Maps to canonical entities in the CKF.

#### `ScenarioTimeline`
- **Purpose:** The chronological projection of clinical state over time (e.g., T+30 days, T+90 days).
- **Relationships:** Contains an array of `SimulationSnapshot`s at discrete temporal intervals.

#### `SimulationSnapshot`
- **Purpose:** The exact projected state of the patient at a specific point in the future.
- **Relationships:** Belongs to a `ScenarioTimeline`. Contains `ExpectedOutcome`s, `RiskProjection`s, and `BenefitProjection`s.

#### `ExpectedOutcome`
- **Purpose:** The deterministic clinical result projected by the CKF/CRP loop.
- **Relationships:** Links to `SimulationEvidence` (citations from CKF proving why this outcome is expected).

#### `TradeOffAnalysis`
- **Purpose:** A computable matrix weighing `BenefitProjection`s against `RiskProjection`s for a specific scenario.
- **Invariants:** Does not recommend a decision; merely presents the mathematical/clinical balance.

#### `UncertaintyProfile`
- **Purpose:** Explicitly models the lack of data. 
- **Lifecycle:** Generated when the CKF returns a "low confidence" or "unknown" traversal for a future projection.
- **Invariants:** If Uncertainty crosses a strict threshold, the `SimulationScenario` must be flagged as `NON_DETERMINISTIC`.

#### `SimulationTrace`
- **Purpose:** Cryptographically signed log of every CRP sub-routine execution that contributed to this scenario, ensuring regulatory replayability.
